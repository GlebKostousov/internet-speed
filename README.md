# Замер скорости скачивания

Утилита принимает прямую ссылку на файл, выполняет 10 последовательных
GET-запросов и полностью читает каждый ответ. Результат — среднее время
запроса, общий объём и скорость скачивания.

Веб-интерфейс показывает ход серии, график времени каждого ответа и позволяет
скачать результат в JSON. Консольный скрипт из исходного задания тоже сохранён;
оба интерфейса используют один алгоритм измерения.

## Быстрый запуск

Нужны Python 3.13 и [uv](https://docs.astral.sh/uv/getting-started/installation/).
Из папки проекта:

```bash
uv sync --locked
uv run --locked python web_app.py
```

Откройте [localhost:8000](http://localhost:8000), вставьте прямую HTTP(S)-ссылку
на файл и нажмите «Измерить». Готовая сборка находится в `frontend/dist`:
для обычного запуска Node.js и сборка интерфейса не нужны.

По умолчанию на каждый полный запрос отводится 30 секунд. В форме можно выбрать
от 1 до 120 секунд. «Остановить» прерывает текущую загрузку; неполная серия
не получает итоговую скорость. Для остановки самого сервера нажмите Ctrl+C
в терминале.

### Тестовый файл

Кнопка «Тестовый файл» запускает серию на локальном файле размером 1 MiB.
Сервер отдаёт его с короткими паузами, чтобы было видно движение графика.
Это проверка работы приложения, а не измерение скорости интернета; интерфейс
помечает такой запуск как локальный пример.

Для внешнего замера укажите файл на другом сервере. Его скачивает **Python
с компьютера, где запущено приложение**. Результат относится к соединению этого
компьютера с выбранным сервером. Промежуточные значения в интерфейсе основаны
на уже завершённых запросах; итог появляется только после всех десяти.

## Консольный скрипт

После `uv sync --locked`:

```bash
uv run --locked python speedtest.py "https://your-server.example/big-file.bin"
uv run --locked python speedtest.py "https://your-server.example/big-file.bin" --timeout 120
uv run --locked python speedtest.py --help
```

Замените адрес своей прямой ссылкой. Кавычки сохраняют параметры URL при передаче
через оболочку. В CLI таймаут — любое конечное положительное число секунд.

Пример вывода для 100 MiB, скачанных за суммарные 20 секунд:

```text
Завершено запросов: 10
Среднее время запроса: 2.000000 с
Суммарное время запросов: 20.000000 с
Скачано: 104857600 байт
Скорость скачивания: 5.000000 MiB/s
```

Это пример расчёта; реальные значения зависят от файла, сервера и соединения.
При ошибке причина и номер запроса выводятся в stderr, успешный итог не печатается.

| Код завершения CLI | Значение |
| --- | --- |
| `0` | Полная серия завершена или показана справка |
| `1` | Ошибка загрузки |
| `2` | Некорректные аргументы |
| `130` | Прерывание через Ctrl+C |

## Что считается

Для каждого запроса монотонные часы `perf_counter` измеряют время от начала GET
до полного чтения тела и закрытия потока. Следующий запрос начинается после
завершения предыдущего. Передача событий интерфейсу, отрисовка и промежутки между
запросами в измеренное время не входят.

```text
T = сумма длительностей 10 запросов, секунды
B = сумма прочитанных байтов 10 ответов

Среднее время = T / 10
Скорость в MiB/s = B / T / 1 048 576
Скорость в Мбит/с = B × 8 / T / 1 000 000
```

Скорость считается по общему объёму и суммарному времени. Среднее арифметическое
десяти отдельных скоростей даст другой результат при разных длительностях
загрузки.

| Показатель | Единицы |
| --- | --- |
| Длительность | В расчётах и JSON — секунды; интерфейс также показывает миллисекунды |
| Объём | Точные байты; интерфейс дополнительно показывает KiB или MiB |
| Скорость | MiB/s; интерфейс также показывает Мбит/с |

1 KiB = 1 024 байта, 1 MiB = 1 048 576 байт. Для перевода MiB/s в Мбит/с
нужно умножить значение на 8,388608: 5 MiB/s ≈ 41,94 Мбит/с.
В JSON сохраняются исходные числа, округляется только отображение.

Тело читается потоком и сразу отбрасывается. Большой файл не сохраняется на диск
и не накапливается целиком в памяти. Размер считается по фактически прочитанным
данным, даже если `Content-Length` отсутствует. Нулевое тело даёт нулевые объём
и скорость.

Отправляется `Accept-Encoding: identity`. Если сервер всё же вернул сжатое тело,
считаются переданные байты до распаковки. HTTP-заголовки, разметка chunked
и служебные данные TCP/TLS в объём не входят.

Один HTTP-клиент обслуживает всю серию. Первое подключение входит в замер;
следующие запросы могут использовать открытое соединение. Проверка TLS включена.
Учитываются переменные окружения HTTPX для прокси и сертификатов, в том числе
`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `NO_PROXY` и `SSL_CERT_FILE`.
Если настроен прокси, внешний адрес измеряется через него. Точные локальные
адреса `localhost`, `127.0.0.1` и `[::1]` соединяются напрямую: локальный пример
работает и без настройки `NO_PROXY`. Остальные адреса сохраняют настройки
прокси и сертификатов окружения.

Нужна прямая ссылка с ответом 2xx. Редиректы и автоматические повторы отключены,
чтобы не добавлять скрытые запросы. HTTP-клиент не кэширует ответы;
`Cache-Control: no-cache` просит промежуточные кэши проверить актуальность данных,
но не отключает кэш сервера или CDN.

Полученная скорость зависит от выбранного сервера, размера файла и состояния
сети. Короткие ответы сильнее зависят от задержек, поэтому для внешнего замера
удобнее большой статический файл.

## Выполнение и отмена

Веб-сервер допускает одну активную серию на процесс. Повторный запуск из другой
вкладки сразу получает HTTP 429, без очереди. Допуск удерживается до завершения
потокового ответа и освобождения ресурсов, в том числе при ошибке или отключении
браузера. У каждой серии свой HTTP-клиент; результаты запросов неизменяемы.

Таймаут ограничивает всю загрузку, включая заголовки и чтение тела. Тот же предел
задан для отдельных сетевых операций. При сетевой ошибке, неуспешном статусе,
обнаруженном обрыве тела или таймауте серия останавливается. Частичные результаты
можно увидеть на графике, но успешного итога у такой серии нет.

Сервер запускается на `127.0.0.1:8000` с одним worker. Веб-режим рассчитан
на локальную работу: проверяются Host и собственный Origin браузера.
Входные параметры проверяются Pydantic; JSON-запрос ограничен 8 KiB и тремя
секундами чтения, чтобы незавершённое тело не удерживало слот измерения.

## Устройство проекта

| Файл или каталог | Назначение |
| --- | --- |
| `measurement.py` | Последовательное потоковое чтение, таймеры и неизменяемые результаты |
| `speedtest.py` | Аргументы и вывод консольного скрипта |
| `web_app.py` | FastAPI, поток событий, локальный пример и запуск сервера |
| `web_support.py` | Контракты API, проверка запроса, допуск и обработка отключения |
| `frontend/src` | Svelte 5, TypeScript, форма и график |
| `frontend/dist` | Готовая сборка для запуска без Node.js |
| `tests`, `frontend/tests` | Проверки измерения, HTTP и обработки событий |

Алгоритм отделён от вывода, чтобы CLI и браузер одинаково считали результат.
Клиент и часы передаются явно: сетевые ошибки и длительности можно проверить
без внешнего интернета. Итоги вычисляются из десяти исходных измерений.

Браузер получает NDJSON: `started`, затем десять событий `sample` и `complete`.
Ошибка приходит отдельным событием `error`; конец соединения без `complete`
считается сбоем. TypeScript проверяет данные и порядок событий на границе API.
Для этой задачи достаточно прямого потока ответа и ограничителя допуска;
отдельные фоновые задания и хранилище состояния не требуются.

## Проверки и разработка

Из корня проекта:

```bash
uv run --locked pytest
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked mypy
```

Проверяются полное чтение, последовательность, расчёт по разным длительностям,
сжатые и пустые ответы, ошибки, таймауты, отмена и входные параметры.
Тесты жизненного цикла поднимают локальный Uvicorn: проверяют отказ второй серии,
закрытие соединения во время загрузки и освобождение слота. Внешний интернет
для тестов не нужен.

Для изменения интерфейса нужны Node.js **22.18 или новее** и npm:

```bash
cd frontend
npm ci
npm run verify
```

`verify` выполняет проверку Svelte/TypeScript, тесты потокового протокола
и сборку в `frontend/dist`. После сборки интерфейс снова доступен через Python.
Для разработки можно запустить `npm run dev`, оставив `web_app.py` в другом
терминале: Vite передаёт API-запросы локальному серверу на порту 8000.

`uv.lock` и `frontend/package-lock.json` фиксируют зависимости. Python проверяется
строгим mypy и Ruff; frontend — `svelte-check` и тестами разбора потока.
